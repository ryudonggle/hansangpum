# 문제와 접근

## 문제

품목제조보고는 제조소(공장)별·재신고별로 따로 올라간다. 그래서 같은 소비자 상품이 여러 레코드가 된다.
레코드 하나를 상품 페이지 하나로 쓰면 두 가지가 나빠진다.

- 검색 결과에 같은 제품이 반복된다.
- 이미지·구매 링크·영양 정보를 레코드마다 따로 붙여야 한다. 예: 하림 닭가슴살갈릭은 레코드 2개 중 1개에만 이미지가 있다.

**목표:** 레코드 N건을 소비자 상품 M개로 묶고, 그 품질을 정밀도·재현율로 잰다.
묶음 단위로 한 번만 매칭하면 이미지·링크가 묶음 전체로 퍼진다.

어려운 점은 "이름이 비슷하다"와 "같은 상품이다"가 다르다는 것이다.

- 같은 공장 안에서 이름이 한 단어만 다르면 대개 다른 맛이다(갈릭 ↔ 수비드 갈릭허브, 군만두 ↔ 물만두).
- 반대로 같은 상품인데 재신고하면서 이름이 바뀌기도 한다.

## 접근

```
수집(C002) → 정제 → 후보 쌍 → 규칙 점수 ─┬─ 확실히 같음 ──────────────┐
                                          ├─ 확실히 다름(cannot-link)  ├→ 묶기 → 적재 → 검색·상세
                                          └─ 애매함 → Jev ─┬─ 자동 ────┘
                                                           └─ 검수 대기 → /admin 사람 판정 → 다시 묶기
```

1. **관계를 셋으로 나눈다.** OEM 공장(예: 엄지식품)은 같은 레시피를 여러 브랜드(마니커·하이밥·허닭…)로 낸다. 이런 쌍은 "같은 상품"으로 묶지 않고 "OEM 형제"로 링크만 건다.
   - **같은 상품:** 묶는다.
   - **OEM 형제:** 묶지 않고 상세 화면의 "같은 회사 비슷한 상품"에 링크로 건다.
   - **다른 상품:** 따로 둔다.
2. **정제([`lib/normalize.ts`](../lib/normalize.ts)):** 중량·입수·판매처·보관(냉동/실온)·포장·이유식 단계를 이름에서 떼어 따로 둔다. 브랜드·맛은 이름 키에 남긴다. 회사명은 법인 표기·공장명을 떼어 같은 회사 계열로 맞춘다.
3. **후보 쌍(blocking, [`lib/score.ts`](../lib/score.ts)):** 같은 회사 계열 안에서만 비교한다. 점수는 이름 bigram 유사도, 원재료 Jaccard, 식품유형 일치로 낸다.
4. **규칙이 먼저 정한다.**
   - 이름이 같거나 회사 접두어만 다르면 묶는다.
   - 보관·포장·단계·이름 속 숫자가 다르거나, 양쪽에 서로 다른 글자가 있으면 따로 둔다.
5. **애매한 쌍만 Jev 판정([`lib/judge.ts`](../lib/judge.ts)):** TypeSafe Jev의 Choice로 세 관계의 확률을 받는다. 판정 기준(instructions·criteria)은 직접 정의했다. 결과는 쌍 키로 캐시해서 같은 쌍은 다시 묻지 않는다.
   - 자동으로 묶는 경우: 같은 상품 확률 0.7 이상이면서 어순·띄어쓰기만 다른 쌍
   - 그 밖의 애매한 쌍은 검수 대기로 보낸다.
   - 비용: 첫 판정 2,828쌍, 입력 300만 토큰, $0.127
6. **묶기([`lib/group.ts`](../lib/group.ts)):** union-find로 묶는다. A=B, B=C로 이어져 서로 다른 A·C가 섞이는 것을 두 단계로 막는다.
   - **cannot-link:** 확실히 다른 쌍이 하나라도 걸리면 두 묶음을 합치지 않는다.
   - **다수결:** 두 묶음 사이 쌍들의 표가 같음 > 다름일 때만 합친다.
7. **사람 검수(`/admin`):** 검수 대기 쌍마다 같음 / OEM / 다름을 고른다. `npm run regroup`을 돌리면 사람 판정이 규칙·Jev보다 먼저 적용되고 사이트에 다시 적재된다.
8. **로그(`/api/events`):** 검색·결과 클릭·상세 보기·외부 링크 이동을 직접 설계한 `events` 표에 쌓는다. `/admin`에서 14일 지표와 검색 0건 검색어를 본다. 세션 id는 브라우저 임의 UUID이고 개인정보는 남기지 않는다.
